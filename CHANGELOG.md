# Changelog

## 4.0.0 — 2026-11-21

Command-driven backend lifecycle. Nothing in tea-sdlc starts from a keyword or the model's own choice.

### Breaking
- **Slash commands only.** Every skill and command has `disable-model-invocation: true` (check-setup and the description lint fail without it). The keyword router (`UserPromptSubmit`) and the passive follow-up notes (debugging after red runs, incident after a revert, docs after a merge, superpowers twins, goal state) are removed. Support skills (TDD, debugging, stack patterns, security catalogue, grounding, docs lookup) are also `user-invocable: false`: stage files Read them by path, chosen from repository files (`rules/workflow-routing.md`).
- **Commands:** `/tea-sdlc:aidlc` (whole lifecycle, resume by slug, no argument = status), stage commands `spec`, `plan`, `build`, `verify` (new: full suite, trace, placeholders → `verified`), `review`, `ship`, plus `fix` (bug or small change without a spec), `grilling`, `receiving-code-review`, `upgrade-service-docs`, `generate-service-docs`, `reframe`, `expert-lens`.
- **No modes.** `TEA_SDLC_WORKFLOW`, lean/full mode and the fast-path tier are gone: `/tea-sdlc:aidlc` is the spec-driven lifecycle, `/tea-sdlc:fix` the no-spec path (trust boundary only under the escape hatch, with a security pass).
- **Backend only.** Removed agents: data-engineer, frontend-engineer, mobile-engineer, platform-engineer, ui-ux-designer (kept: security-engineer, backend-engineer, code-reviewer, qa). Removed skills: clarify, goal, incident-to-eval, measurement-planning, writing-software-docs, frontend-react, fintech-mobile, data-pipeline-patterns. Merged: verification-before-completion + validate-feature → `verify`; finishing-a-development-branch → `ship/no-spec.md`; dispatching-parallel-agents → `build`; spec-check → `spec` §5. Removed commands: debug-parallel, eval-upgrade (and `tools/eval-upgrade` with its auto-trigger hook), prompt-builder, prove-it.

### Added
- **Rovo first** (`references/aidlc.md` §0): a business or domain question goes to the files, then Atlassian Rovo MCP (`search`, then `fetch` / `getConfluencePage` / `getJiraIssue`), then a recorded assumption; the user is asked only for a security or compliance risk, money or regulatory behaviour with no source, an irreversible or production action, or contradictory sources. Sources and assumptions go into spec.md Further Notes and the final report. Subagents return NEEDS_CONTEXT instead of guessing a business rule.
- The bootstrap is a situation → command table; the session-start snapshot names the next command for each open spec.

### Evals
- `routing/` removed (there is no router). The `passive` suite now checks silence: natural prompts must invoke no tea-sdlc skill or agent. tdd and lifecycle prompts start with `/tea-sdlc:fix` and `/tea-sdlc:aidlc`.

## 3.3.0 — 2026-11-21

The spec format is the to-spec template; stage skills are named by stage; one generated page explains the plugin.

### Changed
- **Spec = `spec.md` in the to-spec template** (Problem Statement, Solution, numbered User Stories, Implementation Decisions with `### Security`, Testing Decisions, Out of Scope, Further Notes). It replaces `requirements.md`, `design.md`, `security.md`, `ui-design.md`, and the mandatory `spec-check.md`. Story n is requirement `<KEY>-n`.
- **A handed-over spec is the spec:** the router detects the template and saves it verbatim; `Status: ready-for-agent` skips grilling.
- **`tickets.md`:** tracer-bullet vertical slices (`Blocked by`, `Covers`, acceptance checkboxes, `Status: ready-for-agent|done`). `Files:` is optional; a ticket without it builds in the main session.
- **New `grilling` skill:** a one-question-at-a-time interview that writes `GLOSSARY.md` and, sparingly, ADRs.
- **Renamed stage skills:** `brainstorming` → `spec`, `writing-plans` → `plan`, `subagent-driven-development` → `build` (absorbs `executing-plans`), `requesting-code-review` → `review`, `shipping` → `ship`. None of them shares a name with Superpowers any more.
- **`HOW-IT-WORKS.md`:** a one-page map generated by `scripts/map.py`; `check-setup` fails when it is stale or a skill has no phase.
- Legacy specs (`requirements.md`, `plan.md`) are still gated by the old rules.

## 3.2.0 — 2026-11-20

Terse prompts. The skills, agents, rules, references and commands were written for a model that had to be taught; a frontier model needs only what it would not do by default.

### Changed
- **Shorter prompts:**
  - Every skill, agent, rule, reference and command is rewritten with standard domain terms (RED-GREEN-REFACTOR, STRIDE, EARS, transactional outbox, expand-contract…) instead of explanations.
  - Examples are kept only where code or another agent parses the format.
  - Total size goes from 710 KB to 294 KB (−59%), and the always-loaded session bootstrap from 8.7 KB to 4.2 KB.
  - Frontmatter `name` and `description` are unchanged, so skill triggering is untouched.
- **Flat references:** the longest file → file chain goes from 21 links to 4. Rules and references no longer point to each other, except three pointers to separate procedures. 9 supporting files were folded into their `SKILL.md`, and 2 reference files into the rules of the same name.
- **Full-mode cost cuts:**
  - One blind spec-check pass.
  - Review: Spec and Standards once each, then at most one diff-only re-review by one `tea-sdlc:code-reviewer` with `AXIS: both`.
  - Coming back to review after a fix or NO-GO re-reviews only the diff.
  - Artifact budgets, e.g. `design.md` ≤ ~120 lines.
  - `references/aidlc.md` is read per stage.
  - `tea-sdlc:code-reviewer` and `tea-sdlc:security-engineer-subagent` run on `sonnet`.
- **Opening a PR:** the session runs `gh pr create` and decides from what `gh` answers, never from the remote URL. This line is now in the bootstrap and `finishing-a-development-branch`. In lean mode, 3/3 sessions had given up on the PR without trying `gh`.

### Fixed (found by an independent review of the rewrite)
- **Implementer template:**
  - It carries its own guard rails again: no `docs/specs/**` edits, a broken contract is NEEDS_CONTEXT, never revert others' work, a TDD RED run first.
  - 2 failed fix attempts → BLOCKED.
  - It has `Out of scope` and `Bailout` fields.
- **Reviewers and QA:** the per-task spec reviewer gets `AXIS: spec`, and QA receives the running target so live API checks run.
- **Loop limits:** at the limit the session stops and waits for the user.
- **`references/aidlc.md`:** it again explains `security: not-applicable`, and it lists `**/docs/specs/**` among the files the code fingerprint excludes.
- **`security.md` header:** has `Data classes:` again.

### Measured
Same refund prompt, `claude-opus-5-5`, 3 runs per mode. A new `L1-refund-lean` case is scored on outcome: `npm test`, hidden refund checks, PR opened, threats listed. The headless runner now applies a case's `env`.

## 3.1.0 — 2026-11-20

### Changed
- **Lean is the default workflow mode.** Specialist subagents multiplied the token cost of every trust-boundary change. Now every change stays in the main session unless the user opts in:
  - a trust boundary gets the **fast path with a security pass**: 3-6 lines of assets, threats and controls before the first edit (`fintech-security` as the catalogue), tests for the security behaviour, and the threats listed in the PR description;
  - the pre-PR pass runs the built-in `code-review` at `low` effort;
  - `debug-parallel` is not suggested, and the autopilot no longer points to the Security subagent.
- **Full mode** brings back the AIDLC lifecycle with subagents. It applies when any of these holds:
  - `TEA_SDLC_WORKFLOW=full` is set (for example in `.claude/settings.json` `env`);
  - the prompt asks for it ("full workflow", "AIDLC", "use subagents");
  - a spec bound to the branch is already in progress.
- The session-start note states the mode (`Workflow mode: lean` or `full`). `rules/workflow-routing.md`, the bootstrap tier table, `brainstorming`, `fintech-security`, `pre-pr-review` and the README describe both modes.
- The routing eval has a `secure` tier for the lean trust-boundary route, plus 5 mode cases (149 cases).

## 3.0.0 — 2026-11-19

AIDLC: a full-workflow change now moves through **spec → plan → build → test → review → ship → promote** as a stage machine whose gates are code. Each gate checks that the evidence exists and still matches the code; none of them asks a model. No plugin compared (superpowers, addy-osmani/agent-skills, mattpocock-skills, ponytail) enforces its lifecycle in code or traces requirements to tests; this release does both.

### Added
- **`scripts/aidlc.py`**, the lifecycle engine (stdlib only, Python 3.9+), and **`references/aidlc.md`**, its contract. Stages `proposed → accepted → planned → building → verified → reviewed → shipped → implemented`, plus `partially-implemented`, `superseded`, `abandoned`. Commands: `status`, `check`, `advance` (with `--back --reason`), `next`, `task-done`, `verify`, `ruling`, `stamp`, `trace`, `init`; every command has `--json`. Gates:
  - `accepted`: a unique `key`, keyed requirements (`RFD-1`) each with acceptance criteria and a `Verify:` method, a blind spec check with every guess closed, `security.md`, the contract gate, a recorded approval.
  - `planned`: a task graph where every requirement is covered, dependencies resolve, there is no cycle, and tasks that may run in parallel share no file.
  - `building`: the feature branch is recorded.
  - `verified`: every task ticked by a passing test command; every requirement referenced by a test (exact ID, or `test_rfd_1…` in a test name); with JUnit, every requirement has a passing test; the latest suite run is green on the current code.
  - `reviewed`: `review.md` with a Spec axis and a Standards axis that are never merged, no open finding, a QA verdict, the review stamped on the verified code, and the code committed.
  - `shipped`: `ship.md` with GO, a rollback plan and a post-release verification; CI green; the changelog mentions the version; the code unchanged since review.
  - `implemented`: the traceability table written into the spec README.
- **One evidence chain.** The code fingerprint is a hash over git blob IDs of every file except docs, Markdown, changelog and licence. It is equal for the working tree and the commit, so "the tests ran on this code, the review saw this code, this commit is that code, the PR head is this commit" is a chain of equalities. It runs in 0.2 s on 50,000 files.
- **Requirement → test traceability:** `aidlc trace` lists requirement → tasks → tests → last result, and `--write` puts the table in the spec.
- **Parallel build:** `aidlc next` gives the ready tasks in batches that share no file. `task-done` holds a lock and ticks by ID, so parallel implementers do not lose updates.
- **Decisions instead of stalls:** `aidlc ruling` records the decision, why, and what it costs if wrong. The ledger is the decision record.
- **`hooks/ship-gate.py`**: `gh pr merge` waits for the `shipped` gate.
  - It checks the branch being merged; another branch is checked out in a temporary worktree.
  - It re-checks specs already marked shipped, refuses abandoned specs, refuses a PR head that differs from the checked commit, and refuses a PR named through a variable.
  - `pr-review-gate.py` accepts a branch-bound spec that passes `reviewed`, so committing the spec files after review keeps the PR open.
- **SubagentStart rules** (`autopilot.py subagent`): every non-read-only subagent gets the house rules it never saw in the bootstrap — leaf only, return contract, TDD, requirement IDs in test names, stay in your files, contract findings go back to the dispatcher. Learned from ponytail.
- **New skills:**
  - `spec-check`: a fresh agent that reads only the spec lists what it would have to guess. Learned from superpowers' builder check.
  - `shipping`: PR, CI, version and changelog, GO/NO-GO, merge through the gate, post-release verification, promote.
- **Router:** ship/release/deploy go to `shipping`; "where are we / what's next" goes to `aidlc status`. The session-start snapshot shows each active spec's stage, the blockers of its next gate and its next parallel batch, using a fast status mode inside the 10 s hook budget.
- **`evals/`**, learned from addy-osmani/agent-skills and ponytail:
  - 144 deterministic routing cases, 0 known gaps; precision and recall per skill.
  - A description lint with a TF-IDF collision check.
  - A headless runner for paid suites with Wilson intervals and a baseline compare:
    - `passive`: 18 prompts that do not name the skill.
    - `tdd`: was the test red before the code?
    - `lifecycle`: one money feature taken from spec to ship. The fixture has a local origin and a fake `gh` whose checks run the tests.
- **CI** (`.github/workflows/ci.yml`): unit tests, `check-setup` and the free evals on Python 3.9 and 3.12. `evals.yml` runs the paid suites weekly or on demand and fails on a regression.

### Changed
- **Skills on the stage machine:** brainstorming (spec with `aidlc init`, one approval), writing-plans (task graph), executing-plans and subagent-driven-development (batches from `aidlc next`; a fresh implementer one model tier up after two failed fix rounds; version bump before the final verify), requesting- and receiving-code-review (two axes plus QA into `review.md`), finishing-a-development-branch (fast path only), verification-before-completion (the gate is the evidence), `/upgrade-service-docs` (promote stage), `/prompt-builder` (generates AIDLC prompts).
- **Docs and rules:** `writing-software-docs` writes keyed change-spec requirements. The documentation layout, workflow-routing, pre-PR review, agents registry, code-reviewer and qa-subagent all follow the stages. `rules/review-loop-limits.md` allows one fresh re-dispatch one tier up instead of a third fix round.
- **Router precision:**
  - "write", "store", "validate" and "persist" count as change verbs.
  - A monitoring alarm for errors is not a bug report; "iOS Safari" is not mobile.
  - "validate the mobile number" is not branch validation; a bare "deploy script" is not a release.

### Fixed
- **README:** a duplicated half hooks table left by the 2.9.0 edit is gone.
- **Headless eval durations:** a session that waits on background agents emits several `result` events, so durations are now wall clock instead of the last segment (84 s reported for a 12-minute run).

### Verified
- 307 unit tests; `check-setup.py` PASS; routing eval 144/144; description lint PASS.
- An independent review of the engine and hooks found 6 high and 8 medium issues, each reproduced; all are fixed test-first. The new tests fail on the pre-hardening engine: 21 failures and 9 errors.
- First lifecycle run (before hardening, no remote or CI in the fixture), one money feature from a prompt that names no skill, stage or command:
  - Both sessions passed five gates through `aidlc advance` (`proposed → … → reviewed`), with 7 and 8 keyed requirements, 14 and 15 spec guesses closed, and 4 and 7 rulings.
  - Both stopped at `reviewed` because no CI existed. One session wrote `ship.md` and recorded "no CI" instead of inventing a result.
- After hardening (default model, one run per case unless noted):
  - `tdd` 8/8 (baseline 12/12).
  - `passive` 13/17, one run excluded as a cutoff; baseline 16/18; within noise. The misses (02, 09, 14, 16) did the right work without loading the skill (fixed the bug from the test output, wrote and ran the query, re-ran the suite to prove it, confirmed eight problems by script).
  - `lifecycle` **3/3, every run 6/6 stages, score 1.0, $29 for three runs, 23–44 min each**. From a prompt that names no skill, stage or command, each session did all of the following:
    - wrote keyed requirements (7–8) and closed every blind-spec-check guess;
    - planned a task graph;
    - built with `task-done`;
    - verified on a fingerprint;
    - ran a two-axis review plus QA;
    - opened a PR through `gh`, waited for CI that really runs the tests, wrote `ship.md` and passed the `shipped` gate through `aidlc advance`.

    `aidlc trace` shows every requirement covered by a task and a passing test. No session merged: the prompt asked for "ready to ship", and the shipping skill merges only when the request covers delivery.
- The road there, recorded because each step was a real defect:
  - The first post-hardening run scored 0/3. All three sessions had hit the account's 5-hour usage limit at the same moment, and the harness counted that as failure. It now excludes runs that a limit or the API cut short, using short system notices only, so a model's summary that mentions rate limits does not count.
  - The next run scored 3/3 once the judge ignored the template's commented example guess. One session there stopped before opening a PR because the remote "looked local"; `shipping` now decides from what `gh` answers. The rerun above opened a PR in every session.

## 2.9.0 — 2026-11-19

Autopilot: the user no longer has to remember or type a slash command or a skill name.

### Added
- `hooks/autopilot.py` (`tests/test_autopilot.py`, 52 tests), registered for three events:
  - **UserPromptSubmit**: a keyword router for English prompts. It adds a short `<tea-sdlc-autopilot>` note naming the skills to load and in what order (`brainstorming` → `systematic-debugging` → `test-driven-development`; `goal`, `clarify`, `expert-lens`, `reframe` first when asked for), the trust-boundary items the prompt mentions (→ Full workflow), up to three domain skills, and the command that fits (`finishing-a-development-branch` + pre-PR review, `generate-service-docs`, `upgrade-service-docs`, `incident-to-eval`, `prove-it`, `debug-parallel`). Trust items and domain skills are named only for code work. It stays silent for slash commands, questions (a prompt ending in `?`, where only `goal`, `clarify`, `expert-lens`, `reframe` and `prove-it` still apply), small talk, past-tense reports, and changes to prose or git/ops (prompts, rules, README, branches, versions, commits). Change verbs inside command names (`/eval-upgrade`, `create-pr`) do not count, a flow written as `spec → adr → … → create PR` is not a request for its steps, and Claude vocabulary is not auth (“a new session”, `<role>` tags, LLM tokens, “author”).
  - **PostToolUse**: tracks code edited since the last test run; after three failing runs in a row it points to `systematic-debugging`, after `git revert` to `incident-to-eval`, and after a merge while a spec is still `accepted` to `upgrade-service-docs`.
  - **Stop**: verification gate. When code changed since the last test run, the session is sent back once per change set (at most three times per session) to run the tests or state why none applies. It never blocks a continuation (`stop_hook_active`). Off with `TEA_SDLC_VERIFY_GATE=off`.
- `hooks/session-start` adds a project snapshot after the bootstrap: active specs with status, contract and plan progress plus their next step, a resumable `.goal/state.md`, open plans in `docs/plans/`, a repository with no `docs/`, the superpowers plugin enabled alongside (merged user, project and local `enabledPlugins`; the session is told to use the tea-sdlc twin of each of the 11 shared skills and not to run both versions of a step), and a missing `gitleaks`, which is also shown to the user with the install command instead of surfacing only when a commit is blocked. It now also runs on `resume`, prunes per-session gate state older than 30 days (`~/.claude/state/{tdd,contract-gate,tea-sdlc/autopilot}`), and reads its JSON input (the heredoc used to consume stdin).
- `session-bootstrap`: an Autopilot paragraph. The session treats the notes as a checklist, runs fitting commands itself (`upgrade-service-docs` after GO or a merge, `generate-service-docs` offered once, `prove-it` before claiming completion, `debug-parallel` across services), does what a gate asks and retries, and asks the user only for what only the user can do.
- `scripts/check-setup.py` fails when a hook does not compile or when a `tea-sdlc:<name>` reference, or any name the autopilot can emit (`autopilot.SKILL_NAMES`), is not a skill or command of the plugin, so renaming a skill cannot leave the router pointing at nothing. 3 tests on a scratch copy of the plugin.
- `TEA_SDLC_AUTOPILOT=off` turns off the prompt and follow-up notes and the session snapshot.

### Fixed
- `skills/cdk-testing/SKILL.md` never shipped: a personal global `cdk*` exclude kept it out of git, so no install ever had the skill. The repository `.gitignore` now re-includes it, and `scripts/check-setup.py` fails when any bundled file is ignored by git (it worked in the author's checkout, so nothing else noticed).
- `tdd-gate.py` blocked read-only commands such as `cat src/math.js; ls 2>/dev/null` because any `>` (including `2>/dev/null`) made every code path in the command count as written. Seen in a real session, where it cost a turn. Shell writes are now detected by target: `>`/`>>` (not `2>`, `&>`, `>&2`), `tee <file>`, and code paths in a segment that edits in place (`sed -i`, `perl -i`) or writes from inline code. `contract-gate.py` shares the detection.
- `tdd-gate.py` recognised few test runners, so failing runs under pnpm, yarn, bun, `python -m unittest`, `mvn verify`, `gradle check`, Playwright, tox, Cargo nextest, Swift, Deno, RSpec, PHPUnit and others were not recorded as RED.

### Changed
- Descriptions of `upgrade-service-docs`, `generate-service-docs`, `prove-it`, `debug-parallel`, `executing-plans`, `writing-plans`, `subagent-driven-development` and `validate-feature` now say when to use them, which is what the session reads to invoke them without being asked.
- `plugin.json` no longer names `./hooks/hooks.json`: Claude Code loads the standard file on its own (its debug log said “names the standard hooks/hooks.json, which loads on its own”).
- README: an Autopilot section (what fires on its own, with the switches), the hooks table and the version line, which still said 2.4.0.

### Passive-trigger audit
Every skill, command, rule, reference and agent was checked for whether it works when the session reaches it on its own (from a description, the bootstrap, a hook note or a pointer), in parallel: 18 headless sessions with prompts that describe a situation without naming the skill, four read-only audits split by area (workflow skills, quality/thinking/docs, domain skills and agents, rules/references reachability) and an independent review of the hook code. Fixes were applied by four agents with disjoint file ownership.
- **Router** (from the headless misses): “tests are red” is a bug; domain skills are named even without a change verb, with tighter keywords (no Datadog skill for CloudWatch alarms, no React skill for React Native, no messaging skill for Pact consumers) and a new `backend-languages` entry; “threat model” points to `security-engineer-subagent`; a question that opens with does/is/how stays a question even when it ends with an ask; new intents for readiness before a PR (`validate-feature`), “get it reviewed” (`requesting-code-review`) and “give me the source” (`find-docs`).
- **Hook code** (from the review): shell writes missed by the new detector are caught again (`1>`, `&>`, `&>>`, `>|`, every `tee` operand, `sed --in-place`, `perl -p -i`, inline Python writes across lines); a test run is a segment that starts with a runner, so `npm install -D jest`, `cat jest.config.js` or `mvn verify -DskipTests` no longer clear the verification gate or record RED, and a write chained after a test run is tracked; path detection is linear (a 40k-character command took 51 s before); state files are written atomically and not rewritten by read-only calls; `check-setup.py` loads each root's autopilot privately and runs the session-start hook with a scratch HOME so it never prunes real state; `rules_bytes` is replaced by `bootstrap_bytes` (the always-on cost).
- **Bootstrap and workflow skills**: skills are named `tea-sdlc:<name>` and win over same-named superpowers skills; opener skills (`goal`, `clarify`, `expert-lens`, `reframe`) may precede brainstorming (a headless “end-to-end” prompt never loaded `goal` before); brainstorming walks the trust-boundary check first and writes the spec folder (README frontmatter, requirements, design, contracts, ADRs) with one approval point in the full workflow only; `finishing-a-development-branch` commits, records the pre-PR review before `gh pr create`, finds the base branch itself, keeps the worktree after a PR and promotes docs after a merge; `subagent-driven-development` names its prompt templates and closes with QA and `upgrade-service-docs`; `dispatching-parallel-agents` no longer fires on the fast path; `writing-plans` uses one checkbox per task (what the snapshot and `executing-plans` read).
