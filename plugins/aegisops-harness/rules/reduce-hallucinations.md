# Ground factual claims

- Repository claims come from files and tool output you inspected; version-sensitive APIs, settings and flags from current primary docs or installed help. Cite load-bearing `path:line` or source links.
- Mark inferences and unknowns; never invent paths, symbols, flags, commits or tool results.
- Search before reading large files; read the relevant region.
- Run the relevant checks before claiming success; report what actually ran and its limits. A static parse proves neither model access nor runtime behaviour. Recheck earlier evidence only when changes, failures or doubt warrant it.
- Dispatchers verify cited evidence exists, read the decisive results and keep unresolved concerns.
- Ask for decisions and concise rationale, not chain-of-thought. Detailed workflow: `skills/grounding-claims/SKILL.md`; before completion claims: `skills/verify/SKILL.md` §3.
